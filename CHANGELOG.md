# Changelog

## Unreleased
- **Screens in the document**: `screens` and `start` are document keys (`DOCUMENT_KEYS`; `AppDocument.start?`). `validateDocument` checks each screen root like `app`, at `$.screens.{screen}`, and the layout, node override, ordered key, `on` and node limit checks cover screens. New code `SUI-DOC-SCREEN` for a screen entry that is not `{ title?, params?, root }`, a screen name that is not a part name, an untyped param, and a missing or unknown `start`. A `route` key is `SUI-DOC-KEY`. New `src/core/route/`: `ROUTE_PATH`, `RouteState`, `paramDefaults`, `initialRoute`. `assembleApp` sets `start`, and `validateApp` validates the assembled document directly (the temporary pass over each screen as `$.app` is gone, so screen errors are at `$.screens.{screen}…`, not `….root…`).
- **Docs fix**: the README held a second copy of most of its text, inserted by an edit script; removed.
- **Assembling an app** (`src/core/assemble/`): `assembleApp(blueprint, parts, { library? })` builds the document the runtime mounts from a blueprint and a `PartSource` and returns `{ document, errors, uses }`; `validateApp(blueprint, parts, catalog, options)` assembles and validates it, naming the part that holds each error. New code `SUI-USES-MISSING` (family `SUI-USES`) with the nearest names (`nearestNames`). `AppDocument` gains `screens?` (`DocumentScreen`; type only, not yet a document key).
- **App blueprints and owner parts** (`src/core/blueprint/`): the types `AppBlueprint`, `ThemePart`, `LogicModule`, `ModelPart`, `DatasetPart`, `ComposedPart`, `PatternPart` (types only), `PartKind`/`PART_KINDS`, `PartRef`, and the typed declaration `FieldDeclaration` with `FIELD_TYPES`; `isPartName` and `slugifyName(raw, taken)`; `readBlueprint(json)`, which reports each problem as the new code `SUI-BLUEPRINT-SHAPE` (new family `SUI-BLUEPRINT`) with its path.
- **Search keys** for components: the shape keys `category` (one of `COMPONENT_CATEGORIES`, nine names in index order) and `purposes` (three to eight one-line phrases of at most 60 characters, checked by the exported `checkPurposes`), and top-level `summary`, `category` and `purposes` in a `*.composed.json`, which `parseComposed` checks and strips from the tree. Catalog entries carry them at the top level (a composed entry gains `summary`). New build option `requireSearchKeys` (default `false`) makes a missing key an error. New codes `SUI-BUILD-CATEGORY`, `SUI-BUILD-PURPOSES` and `SUI-BUILD-PURPOSE-DUPLICATE` (a phrase two components share, case and spacing ignored, reported in both modes). Also exported: `isComponentCategory`, `normalizePurpose`, `MIN_PURPOSES`, `MAX_PURPOSES`, `MAX_PURPOSE_LENGTH`, `ComponentCategory`.
- **Search engine** in `@punyts/stateui-app/core` (`src/core/search/`): `tokenize` (camelCase and non-letter split, stop words, a light stemmer), `SYNONYM_GROUPS` and `synonymExpander`, and `createSearchIndex(entries)`, BM25 (k1 1.2, b 0.75) over weighted fields (purposes 3, name 2, summary 1, property and event names 0.5) with ties broken by distinct need words matched, then by id. Each hit lists the purpose phrases it matched. One engine for `ui_components_search` and AI Minion's `ui-builder`; it imports nothing outside its folder.
- **Theme values**: shadows take one optional `inset`, one colour first or last and 2 to 4 lengths (`0 1px 2px #0002`, `inset 0 0 0 1px {color.border.base}`), so a three-length shadow passes and `none` is still refused. Dimensions take `clamp()`, `min()` and `max()` of lengths, `calc()` and dimension references, with `vw`, `vh`, `vmin` and `vmax` inside them and a bare sum as an argument (no inner `calc()`), for fluid type (`clamp(28px, 4vw + 12px, 56px)`). A new token type `inset` holds 1 to 4 space-separated dimensions or dimension references (`{space.inset.md} {space.inset.lg}`); a component token default of two to four dimension references infers it.
- **Logic order**: within one step of a chain a unit runs after the other units whose commands write under its trigger paths, so a rule over `$.data.bag` that sums line totals sees the totals a table writes in the same step instead of the stale ones. Units that depend on each other in a cycle keep document order; a unit still fires at most once per chain.
- **Logic results**: a rule or table can wait for the result of a rule's or table's `save-data` or `delete-data` (`when: { result: name }`, narrowed by `is` and `if`, with `$result`); a machine still waits only for its own commands. A name no rule or table command has is `SUI-LOGIC-SHAPE`, and so is a guard without `path`.
- **`on` commands take `from`**: a path in any target form (`$.data.x`, `^name.path`, `.path`, `$row.path`) whose current value is the command's argument instead of `value`, so `{ command: 'set', target: '^detail.value', from: '$.data.picked' }` copies a value (a copy: later changes at `from` do not follow). `set` fails and writes nothing when `from` has no value; `emit` sends it as the payload. `validateOn` reports a `from` that names no value as `SUI-ON-TARGET` and a command with both `value` and `from` as malformed.
- **`SUI-RUN-CLIPPED`** (warning): a record list whose rows are shorter than their content, for `recordList` to report.
- **Live node mounts**: a node written after start is mounted as a load would mount it. `MountedApp.writeNode(path, node, options?)` resolves component defaults and composed components, applies the node's `<-` links (a `^name` reference resolves against the whole app) and removes the links of the node it replaces; `removeNode(path, options?)` removes a node with its links. A runtime `write` whose value is a whole node below `$.app` goes through `writeNode`, and removing a node through `removeNode`, so swapping a `stat` for a `panel`, adding a linked node or changing a link no longer leaves the node half-mounted ("Binding or controller of runtime failed", an unlinked `<-value` showing "—"). A node's `component` or `<-` key written on its own is still a plain store write: write the node whole. `extractLinks` takes `ancestors`, the nodes above a tree that is one node of a larger app.
- **Fix**: `SUI-DOC-ORDER` no longer flags the position keys of a paged record view. The `records` or `items` of a node with an integer `total` are read by position, so their integer-like keys (what `query` writes) carry no order; elsewhere the rule is unchanged. Arrays were never subject to it.
- **Fix**: the browser logic undoes a change a guard refuses again. The store already held the new value when the guard was asked, so the engine saw no change and never refused; the guard now sees the value the change replaced.
- **Logic functions**: `today()` gives the local date as `YYYY-MM-DD` (`now()` is UTC) and `slice(value, start, end?)` cuts a string or the items of an array or map.
- **Validator**: `SUI-STATE-STEP` (warning) when a number field's `min` is not a multiple of its `step` (step above 0), which makes whole numbers impossible; it suggests `min: 0` or a step that divides `min`.
- **Fix**: a `load` replaces `$.data` with the state's `data` instead of merging it in. A merge kept the tail of a longer seeded list and the keys the state no longer had, so after a filtering query shortened a list, a reloaded view (the server reloads a view when an array changes length) drew the old records below the new ones.
- **Logic fixes**: a write that does not change the value fires no trigger and asks no guard; removing a record does not fire the triggers of its fields or ask their guards (only the removed path itself); `{name}` captures work inside expressions (`{{ $.data.items.{id}.qty }}`); a `set`, `copy`, `toggle` or `increment` through a missing `$.data` parent fails with a message that names the parent (use `merge` or `save-data`); a `^name` that matches several nodes says which, and `SUI-LOGIC-TEXT-PATH` (warning) flags a value like `"$.data.x.{{ id }}"` that gives a path as text.
- **Logic trace**: the engine keeps its last 25 runs (`trace()`, `clearTrace()`): cause, changed paths and one event per unit whose trigger matched, with outcome `fired`, `failed`, `debounced`, `already-fired`, `unchanged`, `parent-removed`, `other-state`, `condition` or `refused`. `refusal(change)` names the guard. `LogicFailure` has `kind` and `name` (was `machine`), so a failed rule, table or guard is named as one.
- **Fixes**: `toggle` of a missing value sets `true`; a node named by `target` with no matching ancestor falls back to the one node in the tree with that key; `SUI-RUN-ON-COMMAND` gives the reason; a stored record collection (`records`, `items`) replaces the document's records instead of merging into them.
- **Logic epic 2**: decision tables (`logic.tables`: `when`, `inputs`, `rows` of `{ match?, if?, do }`, the first matching row runs, a default row last); `$previous` (the value a change replaced, `LogicChange.previous`) and the trigger key `was`; timers (`after` on a machine transition with `from`, repeating when it stays in its state, and `debounce` on a path trigger, up to `MAX_DELAY`, run by the new `LogicHost.schedule` and cancelled by `engine.stop()`); the command `call` (machines only) answered by the new `LogicHost.call` with a `LogicAnswer`, given to the machine as its `as` result with `$result.value` or `$result.reason`. `call` outside Full mode is `SUI-DOC-SERVER`, whose message now names the mode. `mountApp` gives the browser engine `previous` and `schedule` and stops it on unmount. New exports `MAX_DELAY`, `LogicAnswer`, `LogicRow` and `LogicTable`.

## 0.1.0
- **Logic** (`logic` document root, `core/logic`): machines (a state path, an initial state and transitions `from` → `to` when a trigger matches) and rules (a trigger and commands) that act on state changes with built-in commands: `set`, `merge`, `copy`, `toggle`, `increment`, `reset`, `save-data`, `delete-data`, `pull-data`, `query`, `notify`, `emit` and `reject`. A trigger is a state path with `*` and `{name}` steps or the result of a `save-data` or `delete-data` command (`result`, its `as` name), narrowed by `is` and `if` (`@punyts/expression` with a function library). Values take `{{ }}` templates, `$.` and `^node` references, `$trigger`, `$result`, `$key`, `$record`, the captures, and the sources `{ form }`, `{ record }` and `{ pick }`. A transition's commands run on a working copy and commit together; a failure commits nothing and raises `logic.failed`. A rule whose only command is `reject` is a guard. A machine or rule fires at most once per chain, chains stop at depth 8. `createLogicEngine`, `createLogicIndex` (node references, form fields, `reset` values and the records property of a record view) and `readLogic` (errors `SUI-LOGIC-SHAPE`, `-COMMAND`, `-PATH`, `-STATE`, `-EXPRESSION`) are exported. `mountApp` runs the logic in the browser for Standalone and Persisted apps, for the store's untagged writes only; logic writes carry the origin `logic`, which the runtime's sync capture sends. A refused change is undone. App events: `logic.failed` and `notify.<name>` (`isAppEvent`). `query` writes the window's records by position and the `total` into a list (`items` of a `list` or `table`, `records` of a `recordList`).
- Depends on `@punyts/state-sync` ^0.8.0.
- Fix: the runtime no longer syncs the runtime properties of a node (`"runtime": true` in its shape, such as the `body`, `count` and `slots` a list computes). They reached the server, and a fresh view put the stored `count` of 0 over what the list computed, so the list drew at zero height and showed "No items". A change at or below a runtime property is not posted and is cut out of a change above it, and a snapshot or host write does not set one.
- Fix: a `load` snapshot sets a declared property that the document leaves unset, such as the `items` and `total` logic fills into a list. Before, only paths the document already held were written, so the list stayed empty until the next change. A child node that is gone from the document, and a slot property, are still skipped.
- Docs: a README section on sync modes, offline use, `$.runtime.sync` and `sync.rejected` (AMM-1822).
- Runtime sync messages (AMM-1817): the runtime posts one `change` (`{ id, path, op, value? }`) per captured change of the store (`captureChanges` of `@punyts/state-sync`, now a dependency) in place of the whole `snapshot`, which is removed with `MAX_SNAPSHOT_BYTES` (`MAX_CHANGE_BYTES` and `MAX_CHANGE_ID_LENGTH` are new). Host `write` messages are sync writes and post nothing back; they may also write `$.theme`, `$.locale` and the sync status `$.runtime.sync`. `load` takes `mode` (`RuntimeMode`), passed to `mountApp`'s new `options` (`MountOptions`), which validates the document for that mode and sets `$.runtime.sync` to `{ mode, status, waiting }`; a link may target `$.runtime.sync`. New host message `event` raises an app event (`APP_EVENTS`: `sync.rejected`) through `MountedApp.raise`, which runs the root node's `on` entry with the payload; `validateOn` accepts app events on the root. Password values are never posted.
- `$.server` in documents (AMM-1816): a link into `$.server` is `SUI-LINK-SERVER` in every mode, since the branch is server-only and never reaches the browser. `validateDocument` takes `mode` (`standalone`, `persisted` or `full`, the exported `AppMode`); in `standalone` and `persisted` mode, which have no app server, every string naming `$.server` or a path below it is `SUI-DOC-SERVER`.
- Fix: `null` removes an entry of a keyed `map` property (a table's `columns`) when an override is merged onto a composed tree, as it does in `children` and node slots; before, `children.table.columns.actions: null` of `crudTable` failed with `SUI-STATE-INVALID`. `mergeValues` takes an optional shape lookup (and the shape of the base) to tell a `map` property from a value; a `null` anywhere else, such as a nullable property or `$.data`, stays a value.
- Fix: a list, tree, record list, record grid or board whose row template has `$row` links no longer fails with `SUI-LINK-ROW` when it sits directly in a node slot (`splitPane.start`, `popover.body`, `modal.body`); the slot owner read the nested row template as if it were outside one. `$row` outside a row template is still reported, once.
- Fix: in a `row` layout with a growing item (`grow` 1 or more), the items that do not grow keep their content width (`flex-shrink: 0`) and the growing items take the squeeze (`min-width: 0`). Before, every item shrank, so text that can break anywhere, such as an order number beside a growing name, was cut to a few characters. A `row` with no growing item is unchanged.
- Fix (AMM-1808): the node localizer (`createNodeLocale`) ignores a node that a store link shows at a `$.app` path but that lives elsewhere, such as the pooled slots of a record view (shown at `<view>.slots.<n>`, held under `$.runtime`). It used to record them into every language overlay, so a later switch of language applied `slots.<n>` through the link and replaced the pooled slots with the overlay, which removed their `component` and made each report `SUI-NODE-MISSING`.
- Shape key `childComponents` (E8.37, AMM-1777) and the error `SUI-NODE-CHILD`: a shape lists the components its `children` slot accepts, and a `node` property lists the components that slot accepts; `validateDocument` reports a node of any other component in it with the state path and the accepted names. Composed components are checked by the root component they resolve to. The key is carried into the catalog: `shape.childComponents` and `childComponents` on the entry for `children`, and `childComponents` on a slot in `slots`.
- `ui-file-transfer` event (E8.22, AMM-1802): a controller cannot reach the `mountApp` hooks, so a component raises the bubbling, composed event `FILE_TRANSFER_EVENT` with a `FileTransferRequest` detail (`file`, `onProgress`, `signal`, `respond`) and the dispatcher answers it by calling `respond` with the promise of `hooks.transferFile`; with no hook, `respond` is never called.
- Runtime file messages and the `transferFile` hook (E8.39, AMM-1805): the closed message set gains `file` and `fileCancel` (runtime to host) and `fileProgress` and `fileResult` (host to runtime), with `MAX_FILE_BYTES` (10 MiB), a 2 KiB limit for their JSON fields (`MAX_FILE_JSON_BYTES`) and a validator that requires `data` to be an `ArrayBuffer` of exactly `size` bytes. `startRuntime` gives `mountApp` the hook `transferFile(file, { onProgress, signal })`, which posts the buffer in the transfer list, relays progress, resolves with the `FileReference`, rejects with `FileTransferError` (`code` from `FILE_ERROR_CODES`), posts `fileCancel` on abort and rejects with `offline` after `FILE_IDLE_TIMEOUT_MS`. The media type travels in `mediaType` because `type` is the message type.
- Data visualisation colour tokens (E8.10, AMM-1783): the semantic group `color.data` (`categorical.1`-`8`, `sequential.1`-`7`, `diverging.neg3`-`pos3`) references palette primitives and has `light`, `dark` and `contrast` values in the shipped mode overlays, with one-line descriptions in `tokens.descriptions.json` (so they appear in the catalog `theme` section). `checkContrast` also warns (`SUI-THEME-CONTRAST`) when a data colour is below 3:1 against `color.surface.base`; new export `MIN_DATA_CONTRAST`.
- Runtime bundle (E7.2, AMM-1755): `runtime-bundle/entry.ts` and `build.ts` bundle the runtime, `@punyts/stateui-components` and its locale overlays into one content-hashed classic script (`npm run build:runtime-bundle`, output `dist/runtime-bundle/` with `manifest.json`, export `./runtime-bundle/*`). The nonce comes from the URL fragment of the page.
- Runtime `command`, `locale` and `theme` messages (E7.13, AMM-1763): `startRuntime` runs a `command` through the dispatcher's command runner (an unknown target or command posts `SUI-RUN-ON-TARGET` or `SUI-RUN-ON-COMMAND` and changes nothing; `set`, `toggle` and `emit` are refused), applies a `locale` overlay with `switchLocale` (new option `componentOverlays`; `$.data` is unchanged) and a `theme` overlay of a kind and name with `applyOverlay` (an unknown kind or name posts `SUI-THEME-OVERLAY`). They no longer count as `unhandled` once an application is mounted.
- Runtime message protocol and in-iframe runtime (E7.1, AMM-1754): `src/runtime/` defines the closed, versioned message set (`load`, `write`, `command`, `locale`, `theme`, `ready`, `snapshot`, `emit`, `error`, `ping`, `pong`), `validateMessage` with size limits, `isIconsMap`, and `startRuntime(window, parent, nonce, library)`, which mounts on `load`, applies `write` messages, answers `ping`, and posts `ready`, `snapshot` (no password values or `$.runtime`), `emit` and `error`. New entry points `./protocol` (no DOM) and `./runtime`, also exported from the root. New error code `SUI-RUN-WRITE`.
- `catalog.json` has a top-level `theme` section (semantic tokens with type, default, group and description, and the shipped overlays by kind with the groups each kind may touch), built by `buildThemeSection` from `tokens.descriptions.json`; a semantic token without a one-line description is `SUI-BUILD-TOKENDESC`. `emitCatalog` takes the section as its second argument; `BuildOptions.tokenDescriptions` replaces the descriptions.
- Scaffold: package, build and test setup, and the `.` and `./core` entry points (AMM-1649).
- Build option `sharedCssDir`: a line `@include "<name>.css";` in a `view.css` is replaced with that file of the shared folder before the checks and transforms, so the token lint covers the partial. An unknown or non-plain file name, and an `@include` inside a partial, are `SUI-BUILD-IO` with the line.
- Fix: the catalog `example` of a component now includes each property a `requiredWhen` makes required (with its default or a sample value), so the example passes `validateNode`; before, it left them out.
- Fix: `buildAppOverlay` with the `library` option now translates the entries of a content map (`_errors.required`); before, only entries whose key started with `_` were picked.
- Validator `regex` (a maximum length, 1 to `MAX_PATTERN_LENGTH`): a string property whose value must be a regular expression of at most that length that compiles and has no nested quantifier such as `(a+)+`; for a field's `pattern`.
- `mountApp` no longer applies a `$row` link found in a row template (a `row: true` slot or map-item field): the `<-key` stays in the tree as written, so a component can pass the template to `resolveRowLinks`; before, such a document failed to mount with `SUI-LINK-MISSING`.
- Fix: `libraryFromCatalog` carries a catalog entry's declared `placement` into its library shape, so children of a component with a placement shape (tabs) validate.
- Shape key `commandValues` and the error `SUI-ON-VALUE`: a literal `value` of a listed command must be a key of the named `map` property.
