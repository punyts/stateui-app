# Changelog

## Unreleased
- **A rule or a machine transition triggers on a node's state by its name** (docs/design/magnetic-editor-links-and-presses.md,
  stage L0). `when.path` may be a node reference, `#name.property` (`#addBook.pressed`), where it was
  `SUI-LOGIC-PATH` before; a guard's trigger too. `readLogic` resolves it through `options.resolve` and refuses,
  as `SUI-LOGIC-PATH`, one that names no node or several (with `explain`'s reason) and one that holds `*`, a
  capture or a template. `createLogicEngine` resolves it through `LogicHost.resolve` when it is made and again,
  before a change is looked up, whenever `$.route.screen` is another screen than the one it resolved for; a
  reference that then finds no node or several listens to nothing and is reported once through `LogicHost.failed`
  (`SUI-LOGIC-PATH: …`, the reference and the unit's path, no value). A debounce timer keeps the path that matched.
  A logic module that names a node in a trigger is `SUI-MODULE-NODE`. Tests: `src/core/logic/triggerReference.test.ts`,
  `src/dom/mount/screens.browser.test.ts` ("should run a rule whose trigger is #name.pressed …", "should resolve a
  press rule again when the screen changes …").
- **A host writes a node's state by its id** (docs/design/state-definitions-and-instances.md). A `write` path may be
  `#<id>.<path>` (`#save.hidden`): the runtime finds the one node of the app node or a screen whose id (its `@id`,
  otherwise its key) it is, looking as logic does (the screen that shows, the app node, then the other screens), and
  writes there; no node or two nodes with the id is `SUI-RUN-WRITE`, or nothing when the
  write is `optional: true` (a copy of a page that dropped the node). `pathsOfId`
  (`core/on`) lists the paths of an id. Test: `runtime/createRuntime.browser.test.ts` ("should write the state of a
  node by its id …").
- **Fix: logic finds a node of a screen that is not showing.** `#name` in logic looked in the current screen and the
  app node only, so a rule that writes a node of another screen (a figure on the home screen that follows the orders)
  validated and then failed while a different screen showed. It now looks in the other screens last. Test:
  `core/route/navigate.test.ts` ("should find a node of another screen …").
- **Fix: logic finds a node by its `@id`.** `#name` in a rule, table, compute or effect matched the node's key only,
  so a node whose `@id` differs from its key validated and then failed when the logic ran (`logic.failed`, "does not
  resolve"). The logic index names a node as links and `on` targets do: by its `@id`, otherwise its key. Test:
  `core/logic/logic.test.ts` ("should resolve a node by its @id …").
- **Declared child branches, and a warning for data that is a component's own state** (docs/design/state-definitions-and-instances.md). Breaking. A component whose shape declares `node` properties and neither lays out, places nor lists children refuses `children` with `SUI-NODE-BRANCH`. `SUI-LINK-OWN` (a warning) reports a `$.data` value bound only to `hidden`, `open` or a shared look of the nodes that read it. Tests: `src/core/validate/validate.test.ts` ("validateDocument: declared branches and own state").
- **The host reads an app by ids; `emit` is gone** (docs/design/state-definitions-and-instances.md). Breaking. The `on`
  command and the logic command `emit`, `DispatchHooks.onEmit`, `LogicHost.emit` and the runtime message `emit` are
  removed. Every event of a node that carries an `@id` (a shape and a row-template copy included) reaches
  `DispatchHooks.onRaised` as a `RaisedReport` `{ id, event, value?, row? }`; the runtime posts it as `raised`, and
  `AppOpenRequest.onRaised` replaces `onEmit` for an app inside an app. `$.raised` still records every event for logic.
  Tests: `src/dom/on/dispatcher.browser.test.ts` ("should tell onRaised the id, the event and the payload …", "should
  tell onRaised nothing about a node without an @id …", "should hand the detail to the shape's entry …"),
  `src/runtime/startRuntime.browser.test.ts` ("should post raised for an event of a node that carries an @id"),
  `src/runtime/validate.test.ts`.
- **`@share` and `$peers`: what the people on the same thing have** (docs/design/state-definitions-and-instances.md,
  "Seeing other people's app state"). A node's `@share` maps its declared properties to `"peers of .<path>"`
  (`SUI-NODE-META` otherwise); `metadataPaths` lists them as `share` (`{ path, by }`), and assembly writes the
  document's `share` (checked by document validation) and adds `$.peers` to `ephemeral`. A link target `$peers` with a
  node reference resolves to `$.peers.<path>` (`peersPath`) with `allowMissing`. Tests: `src/core/on/ids.test.ts`,
  `src/core/meta/metadataPaths.test.ts`, `src/core/links/references.test.ts` ("should read what the peers have …"),
  `src/core/assemble/assemble.test.ts`.
- **A component's definition marks its own properties** (docs/design/state-definitions-and-instances.md). A
  `state.json` may list `@local`, `@secret` or `@transient` properties it declares (`Shape.marks`, carried in the
  catalog); `metadataPaths(document, library)` adds them for every node of the component, and `assembleApp` passes
  its `library`. The assembled `ephemeral`, `local` and `secret` lists hold up to `MAX_MARKED_PATHS` (2000); an
  app's own `ephemeral` stays at 50. Tests: `src/core/shape/shape.test.ts`, `src/core/meta/metadataPaths.test.ts`.
- **`$.runtime.device`**. `MountOptions.device` names the device the app runs on, a random 16-digit hex id when
  absent; a button's press records it. Test: `src/dom/mount/mountApp.browser.test.ts`.
- **`undo` and `redo` commands** (docs/design/state-definitions-and-instances.md, instances). The system commands
  `undo` and `redo` take no target or value (`HISTORY_COMMANDS`; validation refuses one that carries any as
  `SUI-ON-SHAPE`) and call the new `DispatchHooks.travel`; the runtime posts them as the outbound message
  `history` `{ step }` for the host's sync client. Without a host that keeps a history they fail as `SUI-RUN`. Tests:
  `src/core/on/on.test.ts`, `src/runtime/validate.test.ts`, `src/runtime/startRuntime.browser.test.ts`.
- **A person may change a label, never add one** (instances). Laying an instance over its definition lays `_`
  content only where the definition has that key, so a person's label override shows and a label the definition
  lacks does not. Test: `src/core/snapshot/instance.test.ts`.
- **Translated labels never reach a person's instance.** `switchLocale` writes the language's labels with the
  origin `LOCALE_ORIGIN` (`locale`), which capture skips, so switching language writes nothing to the instance.
  Test: `src/dom/locale/switchLocale.test.ts`.
- **Node metadata compiles into the document's path lists** (docs/design/state-definitions-and-instances.md).
  `metadataPaths(document)` (`core/meta/metadataPaths.ts`) gives the paths the nodes of the app and screens mark with
  `@local`, `@secret` and `@transient`: the node's branch for `true`, the named properties for a list. Assembly
  merges the `@transient` paths into `ephemeral` and writes the new document keys `local` and `secret`, which the
  validator checks like `ephemeral` (`SUI-DOC-MARKED`). Tests: `core/meta/metadataPaths.test.ts`,
  `core/assemble/assemble.test.ts` ("should compile the metadata of the nodes into the local, secret and ephemeral
  paths of the document").
- **Node references are `#name`, and a node can carry an `@id`** (docs/design/state-definitions-and-instances.md).
  `#signIn.busy` replaces `^signIn.busy` in links, `on` targets and logic. A node's id is its `@id` when it has one,
  otherwise its key, so a node can move or be re-keyed and keep the name logic uses. Two nodes of one tree with the
  same `@id` are `SUI-NODE-ID-TWICE`. In a logic value, a hex colour (`#3366ff`) stays a literal. Breaking: `^name`
  no longer parses. Tests: `core/on/ids.test.ts`.
- **Nodes take metadata keys: `@id`, `@local`, `@secret`, `@transient`** (`META_KEYS`, `PREFIXES.meta`). A value that
  does not fit, or another `@` key, is `SUI-NODE-META` or `SUI-NODE-NAME`. Metadata is the definition's: an instance
  never lays it and a snapshot never saves it. Tests: `core/on/ids.test.ts`, `core/limits.test.ts`.
- **`is` and `was` match any item of a list.** `"was": ["paid", "packed"]` fires when the value before the change is
  either. Breaking: a list no longer matches a list value equal to it; compare whole lists in `if`. Test:
  `core/logic/logic.test.ts` ("match is and was against each item of a list").
- **A stamp no longer runs at start for every record.** Fix: a rule with a path trigger and only `set` commands
  derived at start even when it wrote `now()`, so every matching seed record was stamped with today; a rule whose
  conditions or values read `$previous`, `now()` or `today()` now waits for a change. Test:
  `core/logic/logic.test.ts` ("a rule that stamps the time or reads $previous").
- **A list keeps the rows a `query` wrote after a reload** (docs/design/magnetic-starter-apps.md). Fix: `layInstance`
  took only keys the definition has, so a list whose `items` the definition left unset or empty lost them on load.
  A node now also takes a property its component declares (`mountApp` passes the library's, `DeclaredProperties`),
  and inside a property's value new keys are laid. Test: `core/snapshot/instance.test.ts`.
- **A screen name with a dash reads whole in an expression.** Fix: `$.screens.new-order.total` was read as a
  subtraction; `compileExpression` now writes the name in bracket form (`withScreenNames`). Test:
  `core/logic/logic.test.ts` ("a screen whose name has a dash").
- **`query` into `$.data` writes a list.** Fix: its position keys were refused there (`SUI-DOC-ORDER`); into a
  `$.data` path the records are a list in result order, and elsewhere still keyed by position. Test:
  `core/logic/logic.test.ts` ("a query into $.data").
- **A link can reach another node's stored property.** `#notes.value` links to the node's state path, so a preview
  can follow a text area, or a node another screen's value; before, only exposed runtime properties could be reached
  (`SUI-LINK-MISSING`). Content and runtime properties a component does not expose stay refused. Tests:
  `core/links/references.test.ts`, `core/validate/validate.test.ts`.
- **A data binding's scope is `person`.** A binding that gives each person their own records of a model is
  `{ model, scope: "person" }`; `scope: "persona"` is refused with `SUI-BLUEPRINT-SHAPE` at `$.uses.data.{binding}.scope`.
  The type is `PersonBinding` (was `PersonaBinding`). Comments and the README speak of the person's instance. Breaking.
  Tests: `src/core/blueprint/blueprint.test.ts`, `src/core/assemble/assemble.test.ts`.
- **A host can take Ctrl+Shift+= and Ctrl+Shift+-.** With Shift held, the runtime names `+` as `shift+=` and `_` as
  `shift+-`, the keys they are on, and puts `shift+` before `=` and `-` as it does before a letter or a digit, so the
  chords `mod+shift+=` and `mod+shift+-` reach the host. Before, Shift made `+` and `_`, which no chord can name.
  Breaking for a host that named a bare `=` or `-` and expected it with Shift held. Test:
  `src/runtime/startRuntime.browser.test.ts`.
- **An app on the page's body fills the viewport, and apps there sit side by side.** `mountApp` marks its host
  `sui-app` and the document adopts one constructed sheet (`fillPage`, `src/dom/mount/pageFill.ts`): with an app on the
  body or on an element right below it, the body loses its margin and becomes a grid of one row of at least the
  viewport's height and an equal column per element; a host the page gives a size keeps it. The selectors are in
  `:where()`, so a page's own body layout wins. An app deeper in the page is left to the page. `dispose` takes the mark off once no other
  app is mounted on the host. Test: `src/dom/mount/pageFill.browser.test.ts`.
- **A `polyMesh` validator for custom mesh geometry** (docs/design/stateui-mesh-editor.md, V1). An object property
  with `"polyMesh": true` takes a geometry whose `kind` is `custom` only with `vertices` (at most `MAX_EDIT_VERTICES`,
  4000, `[x, y, z]` of finite numbers) and `faces` (at most `MAX_EDIT_FACES`, 4000, lists of 3 to `MAX_FACE_SIDES`, 32,
  distinct indices into `vertices`); anything else is `SUI-STATE-INVALID`. Other kinds pass. The three limits are
  exported from `/core`. Test: `src/core/shape/validators.test.ts` ("polyMesh").
- **Fix: browser logic hears the events nodes raise.** `startBrowserLogic` watched `$.app`, `$.data`, `$.screens` and
  `$.route` but not `$.raised`, so outside Full mode a rule or machine whose trigger was a `$.raised` path (a press, a
  contact) never ran. It now watches `$.raised` too. Test: `src/dom/mount/logic.browser.test.ts` ("should run a rule on
  an event a node raised").
- **Requests that wait for the owner reach the app: `$.runtime.requests`, `request.*` commands and `syncRequested`**
  (docs/design/statenet-requests.md, R2). A `write` may set `$.runtime.requests` and a link may target it; mounts start
  it empty. The app event `sync.requested` (`{ id, path }`) shows `SYNC_NOTICES.requested` on the toasts when the root
  has no entry for it. The system commands `request.approve`, `request.reject` and `request.withdraw`
  (`REQUEST_COMMANDS`) take the id in `value` or `from` (`request.reject` also `{ id, note }`, the note at most
  `MAX_REQUEST_NOTE` 500); `validateOn` reports one with a target or no id as `SUI-ON-SHAPE`. They hand a
  `RequestDecision` to the new `DispatchHooks.decide`, and the runtime posts the new outbound message `decide`. Tests:
  `src/core/on/on.test.ts`, `src/runtime/validate.test.ts`, `src/runtime/startRuntime.browser.test.ts`.
- **A seeded `random` among the logic functions** (docs/design/stateui-game-input.md). `random(seed)` is a number in [0, 1) and `random(seed, n)` a whole number from 0 to n - 1, depending only on the seed (its JSON text, through FNV-1a and mulberry32's mix), so replicas and the authority agree; a missing seed or an `n` that is not a whole number from 1 to 2^32 gives `null`. Tests: `src/core/logic/logic.test.ts` ("values: random").
- **A read grant may be up to 4096 characters** (`MAX_GRANT_LENGTH`; a `grant` message up to `MAX_GRANT_BYTES`, 8 KiB). The grant is now a signed grant token (docs/design/statenet-permissions.md, S14c), about 500 characters with today's owner numbers, which 512 nearly cut off. Test: `src/runtime/validate.test.ts`.
- **The path matcher moved to `@punyts/state`.** Breaking: `compilePattern`, `matchPattern`, `PathPattern` and `PatternMatch` are no longer exported from `@punyts/stateui-app/core`; import them from `@punyts/state`. The logic engine uses them from there; `writeSteps` and `expressionPaths` stay (`src/core/logic/writtenPaths.ts`). The pattern tests moved with it (state `src/Pattern.test.ts`).
- **The runtime gives stored files' `/paths` URLs: `fileUrl`** (docs/design/statenet-paths-route.md, "The frame's side"). `load` takes `files: { url, grant? }`, the new inbound message `grant` replaces the grant, and the hook `fileUrl(id)` gives `<url>/<id>?g=<grant>` for a UUID id, answering `ui-file-url` (`FILE_URL_EVENT`, `FileUrlRequest`). `isFilesSource`, `isGrant`, `MAX_GRANT_LENGTH` and the types `FileUrl` and `FilesSource` are exported. Tests: `src/runtime/validate.test.ts` ("should take the files of a load and a grant only of their shapes"), `src/runtime/fileUrl.browser.test.ts`.
- **A refused change shows a notice by itself.** When the root node has no `sync.rejected` entry, the dispatcher shows `SYNC_NOTICES.unsaved` (`syncUnsaved`) on the app's `toasts` for rejection code `unsaved` and `SYNC_NOTICES.rejected` (`syncRejected`) for any other, never the reason; a root with its own entry runs it instead, as before. `SYNC_NOTICES` is exported from `@punyts/stateui-app/core`. Tests: `stateui-components/test/composites/app-sync-rejected.browser.test.ts`.
- **Grids export their records as CSV through the host.** The runtime message pair `fileExport` (`source`, `name`, `request`: columns, filters and sort, never rows) and `fileExported` (`rows`, or a file error code), the dispatcher hook `exportFile` answering `ui-file-export` (`FILE_EXPORT_EVENT`, `FileExportRequest`) and `createFileExports` (`src/runtime/fileExport.ts`, `FILE_EXPORT_TIMEOUT_MS`). `@punyts/stateui-app/core` gains `src/core/records/`: the filter and sort a grid shows (`passesFilters`, `readFilters`, `foldText`, `optionLabels`, `cellText`, `fieldValue`, `compareSortValues`, `isSortNothing`, `FILTER_KINDS`, `SORT_DIRECTIONS`, `FIELD_PATTERN`) and the export (`readExportRequest`, `exportColumnsOf`, `exportRecords`, `toCsv`, `EXPORT_SOURCE_PATTERN`, `EXPORT_NAME_PATTERN`, `MAX_EXPORT_ROWS`), so the browser and the authority filter and sort the same way. Formula-like text is guarded with a leading `'`. Tests: `src/core/records/recordExport.test.ts`, `src/runtime/fileExport.browser.test.ts`, `src/runtime/validate.test.ts`.
- **stateui-app reports what it does under `stateui-app.*`.** `stateui-app.validate` (a validation: valid, error and warning counts, the count of each code, ms), `stateui-app.assemble` (an assembly: screens, parts used by kind, error codes, ms), `stateui-app.mount` (app mounted, not mounted, unmounted; screen shown and changed; theme applied, overlay applied, theme switched; the 3D chunk loading, loaded or failed with ms), `stateui-app.command` (an `on` entry's commands, a runtime `command` message), `stateui-app.logic.machine` (a transition: machine, from, to, trigger), `stateui-app.logic.rule` (a rule fired), `stateui-app.logic.table` (a table ran, a `lookup`), `stateui-app.logic.compute` (a compute ran, ms), `stateui-app.logic.effect` (an effect started, finished, failed, cancelled or answered from its cache, with ms) and `stateui-app.build` (a library scanned, each component built or not, the library built). Reports hold names, paths, counts and durations, never values; those on a per-event path check `isReported`. The first `mountApp` on a page turns on the categories `localStorage['punyts.report']` lists and logs them with `consoleLogger` (`startBrowserReporting`, `src/dom/mount/reporting.ts`). Fix: a table input outside its values and a `toggle` of a value that is not a boolean put the value in their failure, which `report.error` logged; they now name its kind. Tests: `src/core/report.test.ts`, `src/dom/mount/reporting.browser.test.ts` ("should turn on the categories localStorage lists at the first mount, log them to the console, and report the app by name only").
- **Inspect in a page finds an app's nodes by path only inside its element.** Fix: `inspect` with `paths` took the first element of each path in the whole document and then dropped it when it was another app's, so with another app before it in the page (a board's own page, or a preview of the same screen) the app's nodes were not found. `nodesOf` takes the root to walk, the app's element with `inPage`. Test: `src/runtime/createRuntime.browser.test.ts` ("should find the node at a point under an element of the page laid over the app, as an editor lays its layer").
- **The runtime core takes an app host: `RuntimeCoreOptions.apps`.** `createRuntime` (and `stateuiPage.createRuntime`) passes it to the app it loads as `MountOptions.apps`, so an `embeddedApp` inside an app run by the runtime in a page reaches the page's app host. ## 0.1.0
- **Logic** (`logic` document root, `core/logic`): machines (a state path, an initial state and transitions `from` → `to` when a trigger matches) and rules (a trigger and commands) that act on state changes with built-in commands: `set`, `merge`, `copy`, `toggle`, `increment`, `reset`, `save-data`, `delete-data`, `pull-data`, `query`, `notify`, `emit` and `reject`. A trigger is a state path with `*` and `{name}` steps or the result of a `save-data` or `delete-data` command (`result`, its `as` name), narrowed by `is` and `if` (`@punyts/expression` with a function library). Values take `{{ }}` templates, `$.` and `#node` references, `$trigger`, `$result`, `$key`, `$record`, the captures, and the sources `{ form }`, `{ record }` and `{ pick }`. A transition's commands run on a working copy and commit together; a failure commits nothing and raises `logic.failed`. A rule whose only command is `reject` is a guard. A machine or rule fires at most once per chain, chains stop at depth 8. `createLogicEngine`, `createLogicIndex` (node references, form fields, `reset` values and the records property of a record view) and `readLogic` (errors `SUI-LOGIC-SHAPE`, `-COMMAND`, `-PATH`, `-STATE`, `-EXPRESSION`) are exported. `mountApp` runs the logic in the browser for Standalone and Persisted apps, for the store's untagged writes only; logic writes carry the origin `logic`, which the runtime's sync capture sends. A refused change is undone. App events: `logic.failed` and `notify.<name>` (`isAppEvent`). `query` writes the window's records by position and the `total` into a list (`items` of a `list` or `table`, `records` of a `recordList`).
