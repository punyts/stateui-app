# Changelog

## Unreleased
- **`paintField` documentation** (G2.11 of the graphics epic 2, release 2B): the README's file release paragraph names `paintField` as the field that releases the painting it replaced and the `DELETE /apps/:appId/files/:fileId` route the stateui-mcp live view sends a `fileRelease` to. Documentation only.
- **Graphics documentation, first pass** (G1.11 of the graphics epic 1, release 1A): the README has a Graphics section that indexes what this package holds for drawings (the shape tier, the graphics validators, the paint and label checks, `SUI-RUN-DRAW` and `SUI-RUN-CAP`, shape events, path geometry, file reads) and points to the component library and the MCP server for the rest.
- **Shape events** (G1.7 of the graphics epic 1): the dispatcher now also hears the events shape components declare (`press`, `hover`, `dragEnd`). When an event's `detail` has a string `shape` below the state path of the element that raised it, the `on` entry of that shape node runs (frames from the root down to it); a `shape` outside that subtree runs nothing and is reported as `SUI-RUN-DRAW` with the element's path. For a `drawRepeat` copy (`<repeat>.rows.<key>`, or a shape inside one) the entry of the matching row template node runs, with `$row` at the copy's record and relative targets resolving against the frames down to the repeat. New `recordKeys(records)` and type `RecordKey` (from `core`, moved from the component library's row binder so both name copies the same way). Tests in `src/dom/on/dispatcher.browser.test.ts` and `src/core/on/recordKeys.test.ts`; README under Events.
- **File release** (G2.5 of the graphics epic 2): new messages `fileRelease` (runtime to host: `requestId`, `id`) and `fileReleased` (host to runtime: `requestId` and `ok: true`, or `ok: false` with a code of `FILE_ERROR_CODES` and a message; `fileResult` could not be reused, its `ok: true` form requires a file reference), in `OUTBOUND_TYPES` and `INBOUND_TYPES`, with the 2 KiB JSON limit (`MAX_FILE_JSON_BYTES`) in `MESSAGE_BYTE_LIMITS` and their field checks in `validateMessage`. `createFileTransfers` (`src/runtime/fileTransfer.ts`) gains `releaseFile(id)` and `released(message)`: a release resolves on an `ok` answer and rejects with a `FileTransferError` (the host's code, `offline` after `FILE_RELEASE_TIMEOUT_MS`, which is the transfer idle timeout `FILE_IDLE_TIMEOUT_MS`, `internal` when it could not be posted, `cancelled` on `cancelAll`); the port gains `sendRelease`. `startRuntime` gives the dispatcher the hook `releaseFile` (type `ReleaseFile`, exported from the runtime) and, after an `ok` answer, drops the read cache's bytes of that id (new `FileReads.forget(id)`). The dispatcher answers the bubbling, composed `ui-file-release` event (`FILE_RELEASE_EVENT`, detail `FileReleaseRequest` `{ id, respond }`, both exported from `./dom`) with `hooks.releaseFile`; an unanswered event means no host takes releases. No new error codes. Tests: `validate.test.ts`, `fileRead.test.ts`, `fileRelease.browser.test.ts` (the round trip with a fake host).
- **SVG renderer** (G1.5 of the graphics epic 1): new error `SUI-RUN-DRAW` ("Shape at {path} cannot be drawn as written: {reason}"), which the component library's `drawing` reports once per shape it leaves out (a resolved value it cannot draw, a node that is not a 2D shape) and per linked colour that is not a colour. In `ERROR_CATALOG`, the code list test and the README.
- **Row binder cap** (G1.4c of the graphics epic 1): new error `SUI-RUN-CAP` ("The {component} at {path} has {actual} records, more than the {limit} the {name} renderer draws; only the first {limit} are drawn"), for the component library's `drawRepeat` when its records are over the renderer's cap (2,000 in SVG, 20,000 on canvas). No other change.
- **File reads into the frame** (G1.9 of the graphics epic 1): new messages `fileRead` (runtime to host: `requestId`, `id`) and `fileData` (host to runtime: `requestId`, `ok`, the `FileReference` and `data`, an `ArrayBuffer` of `file.size` bytes in the transfer list, or a code of `FILE_ERROR_CODES` and a message), in `OUTBOUND_TYPES` and `INBOUND_TYPES`, with the 2 KiB JSON limit (`MAX_FILE_JSON_BYTES`) in `MESSAGE_BYTE_LIMITS` and a buffer of at most `MAX_FILE_BYTES` (10 MiB); `validateMessage` drops and counts a bigger buffer as `oversized` and a buffer that differs from `file.size` as `invalid`. `startRuntime` gives the dispatcher the hook `readFile(id, { signal? })` (new `src/runtime/fileRead.ts`, `createFileReads`; types `ReadFile`, `ReadFileOptions`, `FileData` exported from the runtime): reads of one id share one `fileRead`, a read rejects with a `FileTransferError` (`cancelled` on abort, `offline` after `FILE_READ_TIMEOUT_MS` = 30 s, the host's code otherwise), and the bytes are cached by id up to `FILE_CACHE_BYTES` (50 MiB, unused files first, then least recently read) and released a second after a change once no value of `$.app`, `$.screens` or `$.data` holds the id (the definition of stateui-mcp's `isFileReferenced`). The dispatcher answers the bubbling, composed `ui-file-read` event (`FILE_READ_EVENT`, detail `FileReadRequest` `{ id, signal?, respond }`, both exported from `./dom`) with `hooks.readFile`, as it answers `ui-file-transfer`; an unanswered event is the component's `offline` error. No new error codes. Tests: `validate.test.ts`, `fileRead.test.ts`, `fileRead.browser.test.ts`, `dispatcher.browser.test.ts`.
- **Paint and label checks** (G1.3 of the graphics epic 1): two document validators, registered after `step`. `paint` (`validatePaints`) reads every written value of a `color` property (also in map items, such as a gradient stop): a paint name the nearest ancestor's `paints` does not define is `SUI-STATE-PAINT`, a `{token}` the theme does not have is `SUI-STATE-TOKEN` (new codes, errors, at the property's path). The token check uses the new optional `hasToken(name)` of `ValidateDocumentOptions` and `DocumentValidationContext`; `themeTokenLookup(library)` (from `core`) builds it from the default tokens and the root components' tokens; without it tokens are checked by syntax only. Linked values (`<-fill`) are not read. `label` (`validateShapeLabels`) warns `SUI-STATE-LABEL` (new code) for an `interactive: true` node without a `_label`. `PAINTS_PROPERTY` is exported. Shape-tier components declare no component tokens (the design's "Theme and tokens" names only `drawing.background` among the 2D tokens), so token collection stays root-only. The catalog entry of a shape component now keeps its top-level `childComponents` (in `shape` and on the entry), so a group shape such as `drawGroup` takes the shapes it names in its `children` once built; only that entry of the built catalog changes.
- **Shared drawing model: paint** (G1.4b of the graphics epic 1): `colorForm(value)` (exported from `core`, with the type `ColorForm`) gives the form of a `color` value: `token`, `literal` (as the theme's colour check reads it) or `paint`, and undefined for anything else. A literal wins over a paint name, so `transparent` is a colour. The `color` validator uses it, and so do the `paint` document check and the component library's runtime paint resolution, so the three agree. Tests in `validators.test.ts`.
- **Shared shape partials** (G1.2c of the graphics epic 1): a `state.json` (root or shape tier) may list `includes`, names of partial files `<name>.json` (`properties`, `events` and `tokens` only) in the folder of the new `BuildOptions.sharedShapeDir`, merged under the file's own before the shape is read; an own property or token wins, the events are the own ones then the included ones not listed. `parseShape(json, file, options?)` takes `{ partials }` (`ParseShapeOptions`, `ShapePartials`), and `applyShapeIncludes`, `SHAPE_PARTIAL_NAME` and `SHAPE_PARTIAL_KEYS` are exported from the shape module. A bad `includes` list, an unknown partial, a partial with another key or not valid JSON, and a property or token two partials declare are `SUI-BUILD-SHAPE` (no new codes). The catalog shows the merged shape; builds without `includes` are unchanged.
- **Graphics validators** (G1.2b of the graphics epic 1): `VALIDATORS` gains `color` (hex, `rgb()`, `rgba()`, `hsl()`, `hsla()`, a token reference `{group.name}` by syntax only, or a paint name; at most `MAX_COLOR_LENGTH` = 100 characters), `pathData` (parses with `parsePathData`, at most `MAX_PATH_DATA_LENGTH` = 4000 characters and `MAX_PATH_COMMANDS` = 2000 commands; empty or blank data is refused, since a path with no commands draws nothing, although the parser itself reads it as no commands), `points` (at most `MAX_POINTS` = 10000 `[x, y]` pairs of finite numbers), `vector` (option `2` or `3`: exactly that many finite numbers), `fields` (an object of only the listed fields, each `{ type, values?, required?, validators? }` with `type` one of `OBJECT_FIELD_TYPES` and `validators` from `color`, `pathData`, `points`, `vector`, `fields`, `fileRef`, `range`, `oneOf`) and `fileRef` (`{ types, dataUrl? }`: a closed `{ id, name, size, type }` with a UUID id, a non-negative integer size and a listed type; with `dataUrl: true` also a `data:` URL of a listed image type). `color`, `pathData` and `points` take `true` as options. A graphics validator passes a value of a type it does not apply to, so a property of several types (`["string", "object"]`) is checked by type. A refused value is `SUI-STATE-INVALID` at the property's state path; no new error codes. The catalog keeps every option (the field list of `fields` included), and an entry's `example` now gives a value that passes these validators for a required property. New exports from `core`: `MAX_COLOR_LENGTH`, `MAX_PATH_DATA_LENGTH`, `MAX_PATH_COMMANDS`, `MAX_POINTS`, `OBJECT_FIELD_TYPES` and the types `ObjectField`, `ObjectFieldType`, `FieldValidators`, `FileRefOptions`; the theme's colour check `isColor` is exported from `core/theme/value.ts` (not from `core`). Libraries that use none of them build byte-identical.
- **Paths** (G1.2 of the graphics epic 1): new `src/core/geometry/` (no DOM), exported from `core`: `parsePathData(text)` parses SVG path data (`M L H V C S Q T A Z`, absolute and relative, implicit repeats, arc flags without separators) into typed `PathCommand`s, or gives `{ ok: false, index }` at the first bad character (a stray character, a missing argument or arc flag, a number that is not finite, data that does not start with a moveto); `flattenPath(commands, tolerance)` gives polylines per subpath (`FlatSubpath`) within the tolerance, at most `MAX_FLATTEN_SEGMENTS` segments per curve; `pathBounds(commands)` gives the exact bounds. Types `PathPoint`, `PathCommandType`, `PathDataResult`, `PathBounds`. No new error codes.
- **Shape components in the resolver, mount, dispatcher and validator** (G1.1b of the graphics epic 1): `LibraryEntry` gains `ShapeEntry` (`{ tier: 'shape', shape }`, no tag; exported type) and `libraryFromCatalog` and the build's library (pattern and composed checks) keep shape entries instead of leaving them out. `entryShape(entry)` (exported from `core`) gives the shape of a root or shape entry; the resolver merges a shape node over its shape's defaults, and the tree, link, `on`, layout, locale, node-theme, logic-index, command-target and runtime-property code reads a shape node's properties as a root one's. A shape is never an element: `componentTags` (`src/dom/on/dispatcher.ts`, the dispatcher's tags) lists none for it, and the validator reports a shape node in a slot whose `childComponents` does not name it, in a slot with no `childComponents` (the message ends "it takes no shapes") or at the root of the app or a screen as `SUI-NODE-CHILD` at its state path, so `mountApp` mounts nothing for it; `writeNode` refuses such a node with the same error (`refusedChildren`, `childRefusal`, `isShapeComponent` in `src/core/validate/tree.ts`). Component tokens of shapes are not collected yet.
- **Shape components** (G1.1 of the graphics epic 1): a component folder with only `<name>.state.json` (and locale overlays) is a shape component, `tier: "shape"` (`ComponentTier` gains `'shape'`; `ScannedComponent.tag` is absent for it). The build checks its state file, search keys and overlays as a root component's, writes its overlays, and gives it a `ShapeCatalogEntry` (`shapeEntry`, exported type from `./build`) with `summary`, the search keys, `shape`, `own`, `content`, `events`, `locales`, `example` and `tokens`; it writes no module, register entry or CSS for it, and `built` does not list it. A state file with a stylesheet or controller but no view is the new `SUI-BUILD-TIER-SHAPE`. Resolving, validating and mounting shape nodes come with G1.1b: until then `libraryFromCatalog` and the build's pattern check leave shape entries out. Libraries without shape folders build byte-identical. The build fixture library gained the shape `dotMarker`.
- **Layout tests after phone-width rows**: three row tests of `layout.browser.test.ts` used rows of 100–160px, which wrap since rows below the `sm` breakpoint always wrap; they now use 500px rows. Behavior is unchanged.
- **`https:` URLs** (owner decision after the field test of the search-first epic 2): the URL rule (`isSafeUrl`) accepts an `https:` URL with a host and no user info, so a `url` property can name a picture on the web; `http:`, `//host` and every other scheme are still refused. A component narrows it with its `pattern` (`image` and `avatar` take `data:` and `https:`, `link` stays in the app). The pattern input limit (10000 characters) still applies to every value, `data:` images included. Hosts that load apps must allow the images: `img-src data: https:` in the runtime page's policy (stateui-mcp does).
- **The pattern input limit is named** (field test): a `SUI-STATE-INVALID` for a pattern-checked value longer than `MAX_PATTERN_INPUT` (10000 characters; a large `data:` image on `image.src`) now ends with `: the value is N characters, over the 10000 a pattern-checked value may have`. The code and path are unchanged.
- **Deriving rules run at start** (field test of the search-first epic 2): `LogicEngine.start(options?)` runs, before arming timers, each rule or table that only derives values (no machine; every trigger a `path` without `was` or `after`; every command `set`, `merge`, `copy` or `query`), once for every concrete path its trigger matches, in chain order, traced with the cause `start`. A count or total bound to data that was already there used to stay at its default until the first change. Side-effect rules still wait for a change. `start({ derive: false })` skips the pass and the new `LogicEngine.derive()` runs it.
- **Fix: a screen's `on` command on a shell node** (field test): a command target under `$.app` (such as `$.app.children.toasts`) from a node of a screen was resolved against the screen and not found; it is now found from the shell's root, and a target under another screen from that screen's root.
- **Links and menu items are route-checked** (field test): the `route` validator checks a node whose component has a string `screen` property (`link`, `menuItem`) with `checkNavigate`, in the shell and each screen: `SUI-ROUTE-SCREEN` at `<node>.screen` for a screen that does not exist (naming the nearest), `SUI-ROUTE-PARAMS` at `<node>.params`. A misspelt screen used to pass and fail only on a click.
- **A theme's own light and dark** (S2.7b of the search-first epic 2): a `mode` overlay of `themes` (or of a theme of `appThemes`) named `light`, `dark` or `contrast` is no longer a `SUI-THEME-OVERLAY` clash. `buildOverlayCatalog` merges its tokens over the shipped mode of that name, checks the merged tree, and puts it in the shipped one's place, so `system` and an explicit `mode` pick the theme's own. A clash with a shipped `brand` or `motion` name is still an error. Base theme tokens still apply after the mode, so a colour that differs by mode belongs in the mode overlays.
- **Theme presets in the build** (S2.7a of the search-first epic 2): `BuildOptions.presetsDir`, a folder of `<name>.preset.json` theme parts with a one-line `summary`, is read after the components; each preset is checked with `readPreset` (shape, `validateTokens`, `validateThemeOverlay`) and goes into a new top-level `themePresets` section of `catalog.json` (`[]` without the option). New errors `SUI-PRESET-SHAPE` and `SUI-PRESET-FILE`, in a new `SUI-PRESET` family. `buildPresets` and `readPreset` are exported from `./build`. The committed `expected/catalog.json` gained `"themePresets": []`.
- **Pattern check fixes** (found with the first library patterns, S2.3 of the search-first epic 2): `checkPattern` now passes the row context to `validateNode`, so `$row` links inside a row template (a `row: true` slot) and its children are accepted, as `validateDocument` accepts them; and it reports a child that its slot's `childComponents` does not accept, naming the components the slot takes.
- **Patterns in the build** (S2.1b of the search-first epic 2): `BuildOptions.patternsDir`, a folder of `<kind>/<name>/<name>.pattern.json`, is read after the components are built; each pattern is read, checked against the built library and for repeated purposes, and the ones that pass go into the new top-level `patterns` of `catalog.json` (`Catalog.patterns`, entries `PatternCatalogEntry` with the sorted `components` the tree uses), which is `[]` without the option. A file in the wrong place is the new `SUI-PATTERN-FILE`. New exports: `buildPatterns` and `BuiltPatterns` from `./build`, `patternComponents` from `core`. `emitCatalog` takes the patterns as a third argument.
- **Patterns** (S2.1a of the search-first epic 2): `readPattern`, `checkPattern`, `checkPatternPurposes` and `applyPattern` in `src/core/convention/patterns.ts`, exported from `core`, read, check and apply a `*.pattern.json` of kind `shell` or `screen` (`PATTERN_KINDS`): a tree with `slots` and `params` (types `PATTERN_PARAM_TYPES`) mapping names to tree paths. New code family `SUI-PATTERN` with `SUI-PATTERN-SHAPE` (the file and tree) and `SUI-PATTERN-PARAM` (applying values). `PatternParam.type` is now a `PatternParamType` and `PatternPart.kind` a `PatternKind`. `SUI-BUILD-PATTERN` keeps its meaning, a bad regular expression in a shape.
- **Errors name the allowed keys** (from the measured builds, where most failed writes were guesses): `SUI-LAYOUT-SETTING` now ends with the settings of the layout type (`…: the column layout takes "type", "gap", "align"`; `the adhoc layout takes only "type"`), and a `SUI-LOGIC-SHAPE` for an unknown key lists the keys allowed at that place (`unknown key "zz" (the keys here are "when", "do")`). Codes and paths are unchanged.
- **Rows wrap on a phone** (phone-width fix from the measured builds): below the `sm` breakpoint (a container narrower than 480px) a `row` wraps whether or not it names `wrap`, and no row item is wider than its row (`max-inline-size: 100%`). A header of a brand, links and a cart, whose items keep their width beside a growing spacer, was cut off at the right edge. A row that names `collapseBelow` still stacks. Wider rows are unchanged.
- **Default gap** (spacing fix from the measured builds): a `column`, `row`, `grid` or `region` container whose layout names no `gap` now has the `md` gap (`DEFAULT_GAP`, `var(--ui-space-gap-md)`) instead of none; `gap: "none"` still gives 0. A layout host whose node sets no `layout` stacks its children as a column with the same gap (`[layout-host]:where(:not([layout]))` in the base sheet, at the specificity of `[layout-host]`, so a component's own rule such as a hidden empty body still wins). Agents rarely set `gap`, so siblings touched.
- **`logicRunOrder`** (O3.5 of the owner-tree epic 3): `logicRunOrder(logic)`, exported from `core`, lists the units of a logic document in the order the engine looks them up for a change (a unit after the units that write under its trigger path), each with its 1-based `position` and the `$.` paths it `reads` (triggers, table inputs, command `from`) and `writes` (command targets, a machine's state path), then the guards without a position (type `LogicUnitPlace`). The engine builds its units with the same code, so the order is the one it runs. Behavior is unchanged.
- **Shared datasets need Full mode** (O2.9 of the owner-tree epic 2): `validateApp` with `mode: "persisted"` reports each binding to a shared dataset as `SUI-SYNC-SHARED` (new family `SUI-SYNC`) at `$.uses.data.{binding}`; `checkSharedData(blueprint, mode)` is exported from `core`. `LogicHost.guard(change)` is a host's own refusal, asked after the guard rules; `save-data` and `delete-data` give its reason as their `rejected` result.
- **`queryRecords`** (O2.6 of the owner-tree epic 2): the filter, sort and window of the logic `query` command as an exported function of `core` (`core/logic/query.ts`, types `RecordQuery` and `RecordQueryResult`), which the `query` command now uses. Behavior is unchanged.
- **Instances in the runtime** (O2.11 of the owner-tree epic 2): the `load` message takes `instance` (an `AppInstance`), passed to `mountApp` as `MountOptions.instance`. A host `write` may reach `$.screens` (a whole node below `$.screens.{name}` is mounted as below `$.app`), and changes and writes of `$.screens` and `$.route` pass validation; a write of `$.route` is refused by the store, which protects it.
- **Converter** (O1.10): `splitDocument` turns a stored single document (and its state snapshot) into an app blueprint, a theme, datasets with inferred models and owner components, splitting a hidden-strip `tabs` into one screen per tab; `report` lists what it cannot convert, and such an app gets no parts.
- **Theme switching** (O1.13): a new document key `appThemes` (every theme of `uses.themes` by name, filled by `assembleApp`) and `$.theme.active.theme`, which picks one at run time; the theme step rebuilds the tokens on a switch and carries the overlay names over (`activeAfterSwitch`). An unlisted name is `SUI-STATE-INVALID` and set back. `buildOverlayCatalog` takes the base path of its errors. The persona instance keeps the choice and falls back with `SUI-INSTANCE-STALE`.
- **Persona instances** (O1.9): `MountOptions.instance` (an `AppInstance`: `app`, `screens`, `route`, `theme.active`, `data`) is laid over the definition at mount with the new `layInstance`; `diffInstance` gives the sparse difference of two states. A stale screen or overlay name falls back with the new warning `SUI-INSTANCE-STALE` (family `SUI-INSTANCE`). `MountContext` gains `instanceActive`, which the theme step lays over the document's active names.
- **Models and modules in `assembleApp`** (O1.12): `logic` is the app's units plus each module of `uses.logic`, instantiated with its params; a persona binding starts as its model's defaults over an empty map. New codes `SUI-USES-NEEDS` and `SUI-USES-MODEL`; param errors are `SUI-MODULE-PARAM` at `$.uses.logic.{module}.params.{name}`. Assemble errors are `AssembleError` (a `BuildError` with an optional `part`), which `validateApp` keeps. `uses` lists the models of the bindings and modules. `InstantiateModuleOptions.paramsPath` sets the path of param errors.
- **Logic modules** (O1.3): `readModule` and `instantiateModule` in `src/core/logic/modules.ts`, with `MODULE_UNIT_SEPARATOR` (`:`) and a new code family `SUI-MODULE` (`SUI-MODULE-NODE`, `SUI-MODULE-NEEDS`, `SUI-MODULE-PARAM`, and the warning `SUI-MODULE-ONCE`). `readLogic` takes `root`, the path its errors are reported under (`$.logic` by default).
- **Models** (O1.2): new `src/core/models/` with `readModel`, `checkRecord`, `checkDataset`, `applyDefaults` and `inferModel`, and a new code family `SUI-MODEL` (`SUI-MODEL-SHAPE`, `SUI-MODEL-FIELD`). Typed declarations are checked by the new shared `declarationProblems` (with `isKeyName` and `isFieldType`), so `readBlueprint` now also refuses screen params whose validator options are malformed or do not apply to the type, and defaults that do not fit their type or validators. `formatFragment`, `parseFragment`, `sameRoute` and `FRAGMENT_PREFIX` are now exported from `./core` as well. The README's list of code families gains `SUI-ROUTE` and `SUI-SHELL`, which it was missing.
- **Route in the URL** (O1.8): a new `route` mount step (`ROUTE_STEP`, `src/dom/route/`) keeps `$.route` in the URL fragment (`#/product?id=p42`): it reads the fragment on start, pushes a history entry per navigation, and follows `popstate` and `hashchange`; a fragment the app cannot show starts at `start` with a warning, and `dispose` removes the fragment it wrote. `MountOptions.route` (true by default) turns it off; `RuntimeOptions.route` is false by default. New `NAVIGATE_EVENT` (`sui-navigate`, detail `NavigateRequest`): the app navigates on it from any of its elements, with the route on or off. New `formatFragment`, `parseFragment`, `sameRoute` and `FRAGMENT_PREFIX` in `core/route/`. `MountContext.mountOptions` gives steps the options `mountApp` was called with.
- **`SUI-SHELL-OUTLET`**: a new `outlet` document validator (and the `SUI-SHELL` error family). In an app with screens the resolved shell must hold exactly one `outlet` node and no screen may hold one.
- **Screen locales**: a screen takes `locales` (`screens.{name}.locales.{code}`, relative to `$.screens.{name}`), in documents and blueprints. `switchLocale` takes the screens' overlays as a fourth argument (`ScreenOverlays`) and applies them to every screen, hidden or not yet mounted; `MountedApp.screenBaseOverlays` holds each screen's base content. The `locale` validator checks each screen's `locales` at the screen's path.

New `MountedApp.visibleScreen()` and `MountedApp.navigate(screen, params?)`; `writeNode` and `removeNode` take paths below a screen's root. `DispatcherOptions.roots` lets screen nodes raise events, and in a screen `$.screens.{name}…` targets name nodes. The browser logic watches `$.screens` and `$.route` in an app with screens. The runtime's `command` message runs `navigate` (target: a screen name) and component commands on screen nodes. New `OUTLET_COMPONENT`, `screenPath` and `findOutlet` in `core/route/`.
- **`navigate`**: a logic command and a system command of `on` (`LOGIC_COMMANDS`, `SYSTEM_COMMANDS`): `{ command: 'navigate', target: '<screen>', value: { …params } }` writes `$.route` (`{ screen, params }`) in one commit, the screen's param defaults with the given params over them. `routeTo` (new in `core/route/`, with `isRouteRefusal`, `checkNavigate`, `NAVIGATE_COMMAND` and `RouteScreens`) refuses an unknown screen, undeclared or misfitting params and a missing required param; logic fails the transition, `on` reports `SUI-RUN-ON-COMMAND`. New `LogicHost.screens()` and `DispatcherOptions.navigate`, which `mountApp` and the browser logic set for a document with screens. New code family `SUI-ROUTE` with `SUI-ROUTE-SCREEN` and `SUI-ROUTE-PARAMS`, reported by the new `route` document validator for every `navigate` in the shell, the screens and the logic. Logic paths may be under `$.screens` and `$.route`.
- **`^key` with screens**: `createLogicIndex(tree, library, data?, { trees, current? })` (`LogicIndexScreens`) indexes the screens too and resolves a name in the current screen first, then in the shell; without a current screen, in the shell, then among the screens. Each hit lists the purpose phrases it matched. One engine for `ui_components_search` and AI Minion's `ui-builder`; it imports nothing outside its folder.
- **Theme values**: shadows take one optional `inset`, one colour first or last and 2 to 4 lengths (`0 1px 2px #0002`, `inset 0 0 0 1px {color.border.base}`), so a three-length shadow passes and `none` is still refused. Dimensions take `clamp()`, `min()` and `max()` of lengths, `calc()` and dimension references, with `vw`, `vh`, `vmin` and `vmax` inside them and a bare sum as an argument (no inner `calc()`), for fluid type (`clamp(28px, 4vw + 12px, 56px)`). A new token type `inset` holds 1 to 4 space-separated dimensions or dimension references (`{space.inset.md} {space.inset.lg}`); a component token default of two to four dimension references infers it.
- **Logic order**: within one step of a chain a unit runs after the other units whose commands write under its trigger paths, so a rule over `$.data.bag` that sums line totals sees the totals a table writes in the same step instead of the stale ones. Units that depend on each other in a cycle keep document order; a unit still fires at most once per chain.
- **Logic results**: a rule or table can wait for the result of a rule's or table's `save-data` or `delete-data` (`when: { result: name }`, narrowed by `is` and `if`, with `$result`); a machine still waits only for its own commands. A name no rule or table command has is `SUI-LOGIC-SHAPE`, and so is a guard without `path`.
- **`on` commands take `from`**: a path in any target form (`$.data.x`, `^name.path`, `.path`, `$row.path`) whose current value is the command's argument instead of `value`, so `{ command: 'set', target: '^detail.value', from: '$.data.picked' }` copies a value (a copy: later changes at `from` do not follow). `set` fails and writes nothing when `from` has no value; `emit` sends it as the payload. `validateOn` reports a `from` that names no value as `SUI-ON-TARGET` and a command with both `value` and `from` as malformed.
- **`SUI-RUN-CLIPPED`** (warning): a record list whose rows are shorter than their content, for `recordList` to report.
- **Live node mounts**: a node written after start is mounted as a load would mount it. `MountedApp.writeNode(path, node, options?)` resolves component defaults and composed components, applies the node's `<-` links (a `^name` reference resolves against the whole app) and removes the links of the node it replaces; `removeNode(path, options?)` removes a node with its links. A runtime `write` whose value is a whole node below `$.app` goes through `writeNode`, and removing a node through `removeNode`, so swapping a `stat` for a `panel`, adding a linked node or changing a link no longer leaves the node half-mounted ("Binding or controller of runtime failed", an unlinked `<-value` showing "—"). A node's `component` or `<-` key written on its own is still a plain store write: write the node whole. `extractLinks` takes `ancestors`, the nodes above a tree that is one node of a larger app.
- **Fix**: `SUI-DOC-ORDER` no longer flags the position keys of a paged record view. The `records` or `items` of a node with an integer `total` are read by position, so their integer-like keys (what `query` writes) carry no order; elsewhere the rule is unchanged. Arrays were never subject to it.
- **Fix**: the browser logic undoes a change a guard refuses again. The store already held the new value when the guard was asked, so the engine saw no change and never refused; the guard now sees the value the change replaced.
- **Logic functions**: `today()` gives the local date as `YYYY-MM-DD` (`now()` is UTC) and `slice(value, start, end?)` cuts a string or the items of an array or map.
- **Validator**: `SUI-STATE-STEP` (warning) when a number field's `min` is not a multiple of its `step` (step above 0), which makes whole numbers impossible; it suggests `min: 0` or a step that divides `min`.
- **Fix**: a `load` replaces `$.data` with the state's `data` instead of merging it in. A merge kept the tail of a longer seeded list and the keys the state no longer had, so after a filtering query shortened a list, a reloaded view (the server reloads a view when an array changes length) drew the old records below the new ones.
- **Logic fixes**: a write that does not change the value fires no trigger and asks no guard; removing a record does not fire the triggers of its fields or ask their guards (only the removed path itself); `{name}` captures work inside expressions (`{{ $.data.items.{id}.qty }}`); a `set`, `copy`, `toggle` or `increment` through a missing `$.data` parent fails with a message that names the parent (use `merge` or `save-data`); a `^name` that matches several nodes says which, and `SUI-LOGIC-TEXT-PATH` (warning) flags a value like `"$.data.x.{{ id }}"` that gives a path as text.
- **Logic trace**: the engine keeps its last 25 runs (`trace()`, `clearTrace()`): cause, changed paths and one event per unit whose trigger matched, with outcome `fired`, `failed`, `debounced`, `already-fired`, `unchanged`, `parent-removed`, `other-state`, `condition` or `refused`. `refusal(change)` names the guard. `LogicFailure` has `kind` and `name` (was `machine`), so a failed rule, table or guard is named as one.
- **Fixes**: `toggle` of a missing value sets `true`; a node named by `target` with no matching ancestor falls back to the one node in the tree with that key; `SUI-RUN-ON-COMMAND` gives the reason; a stored record collection (`records`, `items`) replaces the document's records instead of merging into them.
- **Logic epic 2**: decision tables (`logic.tables`: `when`, `inputs`, `rows` of `{ match?, if?, do }`, the first matching row runs, a default row last); `$previous` (the value a change replaced, `LogicChange.previous`) and the trigger key `was`; timers (`after` on a machine transition with `from`, repeating when it stays in its state, and `debounce` on a path trigger, up to `MAX_DELAY`, run by the new `LogicHost.schedule` and cancelled by `engine.stop()`); the command `call` (machines only) answered by the new `LogicHost.call` with a `LogicAnswer`, given to the machine as its `as` result with `$result.value` or `$result.reason`. `call` outside Full mode is `SUI-DOC-SERVER`, whose message now names the mode. `mountApp` gives the browser engine `previous` and `schedule` and stops it on unmount. New exports `MAX_DELAY`, `LogicAnswer`, `LogicRow` and `LogicTable`.

## 0.1.0
- **Logic** (`logic` document root, `core/logic`): machines (a state path, an initial state and transitions `from` → `to` when a trigger matches) and rules (a trigger and commands) that act on state changes with built-in commands: `set`, `merge`, `copy`, `toggle`, `increment`, `reset`, `save-data`, `delete-data`, `pull-data`, `query`, `notify`, `emit` and `reject`. A trigger is a state path with `*` and `{name}` steps or the result of a `save-data` or `delete-data` command (`result`, its `as` name), narrowed by `is` and `if` (`@punyts/expression` with a function library). Values take `{{ }}` templates, `$.` and `^node` references, `$trigger`, `$result`, `$key`, `$record`, the captures, and the sources `{ form }`, `{ record }` and `{ pick }`. A transition's commands run on a working copy and commit together; a failure commits nothing and raises `logic.failed`. A rule whose only command is `reject` is a guard. A machine or rule fires at most once per chain, chains stop at depth 8. `createLogicEngine`, `createLogicIndex` (node references, form fields, `reset` values and the records property of a record view) and `readLogic` (errors `SUI-LOGIC-SHAPE`, `-COMMAND`, `-PATH`, `-STATE`, `-EXPRESSION`) are exported. `mountApp` runs the logic in the browser for Standalone and Persisted apps, for the store's untagged writes only; logic writes carry the origin `logic`, which the runtime's sync capture sends. A refused change is undone. App events: `logic.failed` and `notify.<name>` (`isAppEvent`). `query` writes the window's records by position and the `total` into a list (`items` of a `list` or `table`, `records` of a `recordList`).
- Depends on `@punyts/state-sync` ^0.8.0.
- Fix: the runtime no longer syncs the runtime properties of a node (`"runtime": true` in its shape, such as the `body`, `count` and `slots` a list computes). They reached the server, and a fresh view put the stored `count` of 0 over what the list computed, so the list drew at zero height and showed "No items". - Fix: a `load` snapshot sets a declared property that the document leaves unset, such as the `items` and `total` logic fills into a list. Before, only paths the document already held were written, so the list stayed empty until the next change. A child node that is gone from the document, and a slot property, are still skipped.
